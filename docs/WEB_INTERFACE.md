# Веб-интерфейс библиотеки

## Зачем это нужно

Раньше код запускался только через консоль в файле `test.php` с захардкодированными значениями. Теперь тот же самый код (из папок `domain` и `application`) можно запустить через браузер и передавать данные через URL.

**Главная идея:** слои `domain` и `application` не меняются — они одинаковые и для браузера, и для консоли. Меняется только то, как мы вызываем код и как показываем результат.

---

## Как это работает

### Поток выполнения запроса

```
1. Браузер открывает URL
   ↓
2. public/index.php (точка входа)
   ↓
3. Router разбирает URL и находит контроллер
   ↓
4. BookController создаёт репозитории и сервисы
   ↓
5. BookController берёт данные (например, $books = $repository->getAll())
   ↓
6. BookController подключает view с переменными
   ↓
7. View (HTML) выводит результат в браузер
```

---

## Структура папок и их ответственность

### `public/index.php` — точка входа

```php
require_once __DIR__ . '/../src/Router.php';
$router = new Router();
$router->run();
```

**Ответственность:** 
- Первый файл, который браузер открывает
- Создаёт Router и запускает его
- Больше ничего не делает

**Где находится в OpenServer:**
Если твой домен настроен на корень проекта, то браузер откроет этот файл автоматически, когда ты зайдёшь на `http://localhost:порт/`

---

### `src/Router.php` — маршрутизатор

**Ответственность:**
- Парсит URL (какой адрес открыл пользователь)
- Находит в таблице маршрутов подходящий контроллер и метод
- Создаёт объект контроллера
- Вызывает нужный метод, передав `$_GET` параметры
- Если маршрут не найден — возвращает 404

**Как работает маршруты:**
```php
private array $routes = [
    '/books' => [BookController::class, 'index'],
    '/books/show' => [BookController::class, 'show'],
    // ...
];
```

Если пользователь откроет `/books` — router найдёт BookController и вызовет метод `index()`.

**Примеры URL:**
- `http://localhost:8000/books` → BookController::index()
- `http://localhost:8000/books/show?id=1` → BookController::show(['id' => '1'])

---

### `src/BookController.php` — контроллер

**Ответственность:**
- Получить запрос (параметры из `$_GET`)
- Создать репозитории и сервисы
- Вызвать нужный метод (getAll, findById и т.п.)
- Передать результат в view

**Пример метода index():**
```php
public function index(array $params): void
{
    $books = $this->bookRepository->getAll();
    include __DIR__ . '/../views/books/index.html';
}
```

Здесь:
1. `getAll()` — это **тот же самый метод**, что используется в консоли
2. Результат сохраняется в переменную `$books`
3. Подключается HTML-файл, и в нём доступна переменная `$books`

**Важно:** контроллер НЕ печатает сам никакой HTML. Он только подготавливает данные и передаёт их в view.

---

### `views/books/index.html` — представление (view)

**Ответственность:**
- Получить переменные от контроллера (например, `$books`)
- Вывести их как HTML

**Пример:**
```html
<?php if (!empty($books)): ?>
    <table>
        <?php foreach ($books as $book): ?>
            <tr>
                <td><?php echo htmlspecialchars($book->get_name_book()); ?></td>
            </tr>
        <?php endforeach; ?>
    </table>
<?php endif; ?>
```

Здесь используется обычный PHP внутри HTML — это нормально для простых представлений.

## Пошаговый пример

### Пользователь открывает браузер и идёт на `/books`

**Шаг 1:** Браузер отправляет запрос на `http://localhost:8000/books`

**Шаг 2:** `public/index.php` создаёт Router и вызывает `$router->run()`

**Шаг 3:** Router берёт из URL путь `/books`

**Шаг 4:** Router находит в таблице маршрутов: `/books` → `[BookController::class, 'index']`

**Шаг 5:** Router создаёт объект BookController

**Шаг 6:** Router вызывает `$controller->index($_GET)`

**Шаг 7:** В методе `index()`:
```php
$books = $this->bookRepository->getAll();  // берём все книги из БД
include __DIR__ . '/../views/books/index.html';  // подключаем HTML
```

**Шаг 8:** HTML-файл получает доступ к переменной `$books` и выводит её в таблицу

**Шаг 9:** Браузер показывает таблицу с книгами

## Как запустить

### Вариант 1: OpenServer (если уже настроен)

1. Убедись, что в OpenServer домен указывает на папку проекта (или на папку `public`)
2. Открой браузер: `http://localhost:порт/books`

### Вариант 2: Встроенный сервер PHP

```bash
cd путь/до/library-php
php -S localhost:8000 -t public
```

Потом открой браузер: `http://localhost:8000/books`

---

## Какие URL попробовать

Когда сервер запущен:

- **Список всех книг:**
  ```
  /books
  ```

- **Информация об одной книге (если в БД есть книга с id=1):**
  ```
  /books/show?id=1
  ```

- **Несуществующая страница (должна вернуть 404):**
  ```
  /unknown-page
  ```

## Где находится домен слой (`domain`) и сервисный слой (`application`)

В контроллере создаются репозитории:

```php
public function __construct()
{
    $pdo = connectDB();
    $this->bookRepository = new BookRepository($pdo);
}
```

Репозиторий (`BookRepository`) — это инфраструктура.
Интерфейс репозитория (`BookStorage`) — это домен.

Когда контроллер вызывает `$this->bookRepository->getAll()`, он вызывает метод, определённый в интерфейсе `BookStorage` (домен), а реализация находится в `BookRepository` (инфраструктура).

**Главное:** если ты завтра захочешь заменить MySQL на SQLite или PostgreSQL, тебе нужно только переписать `BookRepository`, а контроллер и домен остаются без изменений.

## Как добавить новый сценарий (например, список читателей)

### 1. Добавить маршрут в Router

```php
private array $routes = [
    '/books' => [BookController::class, 'index'],
    '/readers' => [ReaderController::class, 'index'],  // ← новый маршрут
    // ...
];
```

### 2. Реализовать контроллер (ReaderController)

```php
public function index(array $params): void
{
    $readers = $this->readerRepository->getAll();
    include __DIR__ . '/../views/readers/index.html';
}
```

### 3. Создать view

Создать файл `views/readers/index.html` с HTML-кодом

### 4. Открыть в браузере

```
/readers
```

**Важно:** тебе не нужно трогать `domain` или `application` — они уже работают. Меняется только инфраструктура (контроллеры и views).

## Разница между консолью и браузером

### Консоль (`test.php`)

```php
$issueBook = new IssueBook($bookRepository, $readerRepository, $issuanceRepository);
$issueBook->execute('Название', 'Имя', '2026-10-10');
// результат печатается через echo внутри execute()
```

### Браузер (BookController)

```php
$books = $this->bookRepository->getAll();
include __DIR__ . '/../views/books/index.html';
// результат передаётся в HTML-переменную
```

**Видишь разницу?** Код в папках `domain` и `application` не меняется. Меняется только то, как мы вызываем код и как показываем результат (через echo в консоли или через переменную в HTML).

## Частые вопросы

**Q: Почему контроллер не может быть абстрактным базовым классом?**
A: Пока контроллеров мало (3 штуки), это не нужно. Когда будет 10-20 контроллеров и станет видно общие паттерны, можно будет выделить базовый класс. Сейчас это преждевременная оптимизация.

**Q: Почему Router не работает с параметрами вроде `/books/:id`?**
A: Это усложнило бы код. Сейчас используются query-параметры (`/books/show?id=1`), это проще. Потом, когда станет очевидно, что это неудобно, можно будет добавить парсинг параметров в URL.

**Q: Что будет, если в view написать `<?php $book->price = 1000; ?>`?**
A: Это будет работать, но это плохо — view не должна менять данные, только показывать. Это правило, которое ты учишься соблюдать через практику.

- Создать form для добавления новой книги
