# Ошибки в проекте library-php

Ветка: `feature/web-interface`, коммит `a7a7103` (Add namespaces and Composer autoload).

Ниже перечислены ошибки, из-за которых часть функций не работает.

---

## 1. Нет `use` для классов Book и Reader в контроллерах

**Где:**
- `src/BookController.php`, строка 47: `new Book(...)`
- `src/ReaderController.php`, строка 47: `new Reader(...)`

**Что происходит:** контроллеры находятся в пространстве имён `App\Controller`. Без `use` PHP ищет классы `App\Controller\Book` и `App\Controller\Reader`, которых не существует. Поэтому при отправке формы будет Fatal error: `Class "App\Controller\Book" not found`. Добавить книгу или читателя через сайт сейчас нельзя.

**Как исправить:** добавить импорт в начало файлов.

```php
// src/BookController.php
use App\Domain\Book;

// src/ReaderController.php
use App\Domain\Reader;
```

---

## 2. `InvalidArgumentException` без обратного слеша

**Где:**
- `domain/Issuance.php`, строка 15
- `application/DeleteBook.php`, строка 13
- `application/DeleteReader.php`, строка 13

**Что происходит:** `InvalidArgumentException` — встроенный класс PHP, он лежит в глобальном пространстве имён. Внутри `namespace App\Domain` (или `App\Application`) запись `new InvalidArgumentException(...)` означает `App\Domain\InvalidArgumentException`. Такого класса нет. В момент, когда исключение должно выброситься (неверный срок возврата, удаление несуществующей книги или читателя), вместо понятной ошибки будет Fatal error `Class not found`.

**Как исправить:** писать с обратным слешем

```php
throw new \InvalidArgumentException('Книга не найдена');
```

или добавить в начало файла `use InvalidArgumentException;`.

---

## 3. Имя файла не совпадает с именем класса (PSR-4)

**Где:** `Infrastructure/database.php`, класс `Database`

**Что происходит:** автозагрузка Composer по стандарту PSR-4 ищет класс `App\Infrastructure\Database` в файле `Infrastructure/Database.php` (с заглавной буквы). На Windows это работает, потому что файловая система не различает регистр. На Linux, то есть почти на любом хостинге, файл не найдётся, и приложение упадёт на подключении к базе.

**Как исправить:** переименовать файл в `Database.php`. На Windows Git может не заметить переименование только регистра, поэтому лучше так:

```
git mv Infrastructure/database.php Infrastructure/Database.php
```

---

## 4. Возврат книги нельзя сделать через сайт

**Где:** `application/ReturnBook.php`, `src/Router.php`, `src/IssuanceController.php`

**Что происходит:** сервис `ReturnBook` написан, но он нигде не используется: нет маршрута, нет метода в контроллере, нет кнопки в интерфейсе. Выданную книгу нельзя вернуть, поэтому её больше никогда не удастся выдать (`IssueBook` будет писать, что книга занята).

**Как исправить:**
1. Добавить в `IssuanceController` метод (например, `returnBook`), который вызывает `ReturnBook`.
2. Зарегистрировать маршрут в `Router`, например `'/issuances/return'`.
3. В списке выдач (`views/issuances/index.html`) вывести кнопку «Вернуть» у невозвращённых выдач.
